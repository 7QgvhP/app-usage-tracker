# App Usage Tracker

Windows PC とスマートフォンのアプリ使用時間を記録し、ブラウザで確認するための個人用ツールです。

- **PC版** v2.30.0（Python / Flask）
- **Android版** v1.3.0（Kotlin / Jetpack Compose） … `android/` 配下

---

## 起動と停止

起動すると常駐し、`http://127.0.0.1:5000` でダッシュボードを開けます。
同時に、現在使用中のアプリを示す小型ウィンドウが最前面に表示されます。

### 起動

**ショートカット `App Usage Tracker.lnk` から起動します。** 起動用のバッチファイルは
ありません。ショートカットの中身は次のとおりです（環境固有の絶対パスを含むため、
リポジトリには入れていません。下表のとおり作成してください）。

| 項目 | 値 |
|---|---|
| ターゲット | `pythonw.exe` |
| 引数 | `main.py` |
| 作業場所 | プロジェクトフォルダ |
| アイコン | `static/tracker.ico` |

`python.exe` ではなく `pythonw.exe` を使うことで、黒いコンソール画面を出さずに
常駐させています。

**サインイン時の自動起動**は、同じ内容のショートカットをスタートアップフォルダへ
置くことで実現しています。場所は以下です。

```
%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup
```

自動起動をやめるときは、このフォルダのショートカットを削除してください。

コマンドから直接起動することもできます。

```bash
pythonw main.py
```

### 停止

```bash
./stop_tracker.bat
```

**設定を変更したら再起動が必要です。** 起動時にしか読み込まないためです。

## 画面

| 画面 | 内容 |
|---|---|
| ダッシュボード | 合計と前の期間との増減、アプリ別の棒グラフ、制限時間の使用状況 |
| タイムライン | 1日を24時間の円環で表し、いつ何を使ったかを示す |
| 履歴 | 直近30日を「日 × 時間帯」の濃淡で表す。アプリを選ぶとその推移だけを見られる |

**表示はPCとスマホを合算したものです。**

**制限時間だけはこのPCの使用時間に対して働きます。** 通知を出すトラッカーがPCの
使用時間で判定しているため、画面の「超過」と制限一覧の使用状況も同じ基準に揃えています。
スマホでの使用時間は含みません。

### 前の期間との増減

合計の横に「前日比 -7時間16分」のように出ます。期間の切り替え（日 / 週 / 月）に
連動し、それぞれ前日・前週・前月と比べます。

**今の期間が途中の場合、前の期間も同じ日数だけを対象にします。** 週の途中に
前の週を丸ごと比べると、日数の違いで増えて見えるためです。木曜であれば
「今週の月〜木」と「前週の月〜木」を比べます。対象の範囲は数値にマウスを乗せると
確認できます。比べる記録が無い期間では表示しません。

### 制限時間の使用状況

設定した制限ごとに、その日の使用時間と横棒が出ます。

```
X (Twitter)          17分 / 30分
████████████████░░░░░░░░░░░░░
```

- 残り5分を切ると棒が濃くなります（通知の予告と同じ基準）
- 超えると棒と数値が朱色になります
- 残り時間、または超過した時間は数値にマウスを乗せると出ます

### 時間の表記

秒数を文字列にする規則は次のとおりです。**PC本体・画面・スマホで同じ**です。

| 秒 | 表示 |
|---|---|
| 0 | `0分` |
| 1〜59 | `1分未満` |
| 60 | `1分` |
| 3600 | `1時間`（`1時間0分` とはしない） |
| 3661 | `1時間1分` |
| 3600+59分59秒 | `1時間59分`（秒は切り捨て） |
| 25時間 | `25時間`（日へは繰り上げない） |

「1分未満」を設けているのは、`0分` では使ったのかどうか分からないためです。

**この規則は3つの言語に別々に実装されています**（Python / JavaScript / Kotlin）。
コードは共有できないため、[tests/duration_cases.py](tests/duration_cases.py) の表を
唯一の仕様とし、3つすべてを同じ内容で検証しています。表記を変えるときは
この表を直せば、揃っていない実装がテストで落ちます。

### 合計時間の数え方

**場所によって数え方が違います。** 意味が違うため、あえて揃えていません。

| 表示 | 意味 | 同時使用の重なり | 短い区間 |
|---|---|---|---|
| ダッシュボードの「合計」 | 実時間 | **除く** | 含む |
| 履歴の日付右側 | 実時間 | **除く** | 含む |
| タイムラインの円の中心 | 実時間 | **除く** | **30秒未満を除く** |
| ダッシュボードの棒グラフ | アプリごとの稼働時間 | **除かない** | 含む |

**「実時間」は、いずれかのアプリを起動していた時間です。** PCとスマホで同時に
1時間使っても、経過したのは1時間なので1時間と数えます。1日の合計が24時間を
超えることはありません。

**「アプリごとの稼働時間」は、そのアプリが動いていた時間です。** PCでChrome、
スマホでYouTubeを同時に1時間使った場合、どちらも実際に1時間動いているので
それぞれ1時間と数えます。

```
10:00-11:00 Chrome  (PC)      ┐ 同時に使用
10:00-11:00 YouTube (スマホ)  ┘

合計（実時間）        1時間
棒グラフ              Chrome 1時間 ／ YouTube 1時間
```

#### 棒グラフを足しても「合計」と一致しません

理由は2つあります。

1. **同時使用の重なりを除いていない**ため、足すと合計より大きくなります
2. **10分以上のアプリを上位10個まで**しか表示しないため、それ未満は棒に出ません

「合計」の数値にマウスを重ねると、その期間に除外した同時使用の時間が出ます。

#### タイムラインだけ少し小さくなります

タイムラインは**30秒未満の区間を表示から除く**ため、その分だけ値が小さくなります。
画面に描かれている弧と数値を一致させるためで、重なりの扱いによる差ではありません。

ダッシュボードと履歴は絞り込みをしないので、**この2つは常に同じ値**になります。

#### 同じアプリを2台で同時に使った場合

棒グラフだけ重なりを除けません。日ごとの集計（`usage_log`）には時刻が無く、
重なりを判断できないためです。タイムラインのアプリ別は区間から求めるため除きます。

```
14:00-15:00 Notion (PC)      ┐ 30分だけ重なる
14:30-15:30 Notion (スマホ)  ┘

タイムラインのアプリ別   1時間30分
ダッシュボードの棒グラフ 2時間00分
```

## アプリ名の対応表（`data/app_names.json`）

同じアプリでも、PCとスマホでは記録される名前が違います。
そのままでは別のアプリとして数えてしまうため、**照合用のキー**で束ねています。

```
chrome.exe（PC）  ┐
                  ├→ キー "chrome" → 表示名「Chrome」
Chrome（スマホ）   ┘
```

このファイルは**アプリが自動で作成・更新します。** 中身を編集すると束ね方や
表示名を変えられます。編集後にアプリを再起動すると、**過去の記録にも遡って反映されます。**

### 中身の見かた

```json
{
  "aliases": {},
  "apps": {
    "chrome": {
      "display": "Chrome",
      "source": "auto",
      "judgement": "auto",
      "names": {
        "pc": ["chrome.exe"],
        "nothing-a069": ["Chrome"]
      }
    }
  }
}
```

| 項目 | 意味 |
|---|---|
| キー（`"chrome"`） | 照合用の値。**画面には出ません** |
| `display` | 画面に出る名前 |
| `names` | 端末ごとに、実際に記録された名前 |
| `judgement` | どう束ねたか（下記） |
| `source` | `manual` にすると `display` を自動で上書きしません |

`judgement` は3種類です。

- **`auto`** … 規則で複数の表記が一致した
- **`manual`** … あなたが指定した（`display` を変えた、または `aliases` で結んだ）
- **`single`** … 表記が1つだけで、まだ照合していない

### 自動で束ねられる規則

1. 全角・半角を統一する
2. 末尾の `.exe` を落とす … `chrome.exe` = `Chrome`
3. 末尾の括弧書きを落とす … `X (Twitter)` = `X`
4. 大文字小文字と記号・空白を無視する … `minecraft.exe` = `Minecraft.exe`

**名前が似ていても実体が違うものは束ねません。** `YouTube Music` と `YouTube`、
`Notion Setup 7.30.0.exe` と `Notion` は別扱いのままです。

### 編集のしかた

#### 表示名を変える

`display` を書き換え、`source` を `"manual"` にします。
`manual` にしないと、次に記録されたときに自動で選び直されます。

```json
"chrome": {
  "display": "グーグルクローム",
  "source": "manual",
  ...
}
```

#### 別々になっているものを統合する

規則では結び付かない組み合わせは、`aliases` に「記録された名前」→「まとめ先のキー」
を書きます。まとめ先のキーは `apps` の中から選びます。

```json
"aliases": {
  "LineLauncher.exe": "line",
  "LineMediaPlayer.exe": "line"
}
```

#### 誤って統合されたものを分ける

`aliases` から該当の行を消します。自動で束ねられたものを分けたい場合は、
`aliases` でどちらか一方に別のキーを割り当てます。

```json
"aliases": { "Chrome": "chrome-mobile" }
```

#### 編集後

**アプリを再起動してください。** 起動時に対応表を読み直し、過去の記録の
束ね方も合わせ直します。統合によって同じ日の記録がぶつかる場合は集計し直します。

**ファイルが壊れていても起動できます。** 読み込めない場合は警告をログへ残し、
規則による照合だけで動き続けます。

## 設定（`config.json`）

主な項目です。変更後は再起動してください。

| セクション | 内容 |
|---|---|
| `web` | 待ち受けアドレスとポート（既定 `127.0.0.1:5000`） |
| `tracker` | 監視間隔、書き出し間隔、通知の予告時間、無操作の検知 |
| `timeline` | 表示する区間の最小秒数、区間をまとめる間隔 |
| `sync` | スマホからの受信（既定は無効） |
| `devices` | 端末名を画面用の表記へ変換する対応表 |
| `mini_window` | 小型ウィンドウの表示、不透明度、文字サイズ |
| `notion` | Notion への日次登録（既定は無効） |
| `backup` | データベースの自動複製（下記） |
| `logging` | ログの水準とファイルの上限 |
| `apps` | アプリ名の判定（下記） |

### `apps` の主な項目

- **`use_executable_name`** … 実行ファイルの情報から読みやすい名前を得る
  （`r5apex_dx12.exe` → `Apex Legends`）。既定で有効
- **`ignore_processes`** … 計測しないプロセス名
- **`browser_site_rules`** … Chrome のウィンドウタイトルからサイトを判定する規則

`config.json` は「**名前をどう決めるか**」だけを持ちます。決まった名前を任意の表記へ
読み替えるのは `data/app_names.json`（前節の対応表）の役目です。

アプリ名が決まる順序は次のとおりです。上から順に判定し、該当した時点で確定します。

1. `ignore_processes` に一致 → 記録しない
2. ブラウザ（`browser_processes`）→ タイトルを `browser_site_rules` と照合
3. 実行ファイルの `FileDescription`（` - ` 以降は切り捨て）
4. 実行ファイルの `ProductName`
5. プロセス名そのまま

こうして決まった名前が、上記の**対応表で束ねられて**画面に出ます。
表示を変えたいときは `data/app_names.json` の `display` を直してください。

## Notion への日次登録

**1日1ページ**を作り、前日分の使用状況を登録します。**既定では無効**です。

日付が変わったタイミングで自動送信し、PCが落ちていて送れなかった日は
起動時に遡って補います（既定7日まで）。同じ日を送り直すと**既存のページを更新**するため、
重複した行はできません。

### 記録される内容

| プロパティ | 型 | 例 |
|---|---|---|
| 日付 | タイトル | `2026-08-26（水）` |
| 日 | 日付 | `2026-08-26` |
| 合計 | 数値（分） | `550` |
| 合計（表示） | テキスト | `9時間10分` |
| PC | 数値（分） | `517` |
| スマホ | 数値（分） | `121` |
| 同時使用 | 数値（分） | `88` |
| アプリ数 | 数値 | `14` |
| 最長アプリ | セレクト | `X (Twitter)` |
| 最長時間 | 数値（分） | `212` |
| 活動時間帯 | テキスト | `0〜4時、7〜10時、18〜24時` |
| 超過 | 数値 | `1` |
| 要約 | テキスト | 下記の文章 |

**「合計」を分の数値にしているのは、Notion のグラフや集計が数値型でないと使えないため**です。
読みやすさは「合計（表示）」で補います。

ページ本文には、要約の文章とアプリごとの内訳が入ります。

```
8月26日（水）は9時間10分使用（PC 8時間37分・スマホ 2時間1分）。前日より2時間22分多い。
0〜4時、7〜10時、18〜24時が中心。最も長かったのはX (Twitter) 3時間32分、Claude 3時間3分、
Chrome 1時間26分。制限時間を超えたアプリが1件。

アプリごとの内訳
・X (Twitter) 3時間32分（0時 16分 / 1時 13分 / 2時 19分 / ... / 23時 38分）
・Claude 3時間3分（0時 17分 / 1時 16分 / ... / 23時 1分）
```

**要約は言語モデルを使わず、決まった形で組み立てます。** 生活の記録は数値がずれては
いけないためで、毎日同じ形になることは読み返すうえでも利点になります。

1日あたりの送信量は約2.7KB（上限500KBの0.55%）、リクエストは1〜2回です。

### 有効にする手順

1. [Notion のインテグレーション](https://www.notion.so/my-integrations)を作り、
   **内部インテグレーションシークレット**を発行する
2. 上の表のとおりデータベースを作る
3. そのデータベースを開き、右上「…」→「接続」から 1 のインテグレーションを追加する
4. 発行したトークンを **`data/notion_token.txt`** へ貼り付ける（改行のみでも可）
5. `config.json` を編集して再起動する

```json
"notion": {
  "enabled": true,
  "database_id": "データベースURLに含まれる32桁",
  "backfill_days": 7
}
```

**トークンは `config.json` に書きません。** 設定ファイルは画面共有などで映る可能性が
あるためで、同期用トークンと同じ扱いです。

待たずに試すには、次で未送信分をすぐ送れます。

```bash
curl -X POST http://127.0.0.1:5000/api/notion/send
```

### 注意

**アプリの表示名を変えると、「最長アプリ」の選択肢が二重になります。**
Notion は API から渡された名前が無ければ選択肢を自動で追加するためです
（過去の行は古い名前のまま残ります）。**Notion 側で選択肢の名前を変更すれば**、
既存の行にも反映されて解消します。

**PCが止まっている間の記録は欠けます。** Notion へ送る値も同じ欠落を含みます。

## スマホとの連携

同一Wi-Fi内で、スマホからPCへ使用状況を送ります。**既定では無効**です。

### 有効にする手順

1. `config.json` の `sync.enabled` を `true` にする
2. アプリを再起動する（`data/sync_token.txt` が生成されます）
3. ファイアウォールに受信規則を追加する（**管理者権限のPowerShellで実行**）

```powershell
New-NetFirewallRule -DisplayName "App Usage Tracker (sync)" -Direction Inbound -Protocol TCP -LocalPort 5000 -Action Allow -Profile Private
```

4. スマホのアプリに、PCのIPアドレス・ポート・`sync_token.txt` の値を入力する

### 通信の範囲

有効にするとポートをLANへ開きますが、**外部から使えるのは同期APIだけです。**
ダッシュボードと通常のAPIはこのPCからしか利用できず、他の端末からは拒否されます。
同期APIは共有トークンで認証します。

トークンを変えたいときは `data/sync_token.txt` を削除して再起動してください。

### 同期の仕組み

- スマホは**15分ごと**に自動で送信します
- PCが起動していない間は端末に保存し、次に繋がったときにまとめて送ります
- 同じ区間を何度送っても二重に記録されません
- **OSが保持する記録は数日分です。** スマホのアプリが長期間動かないと、
  その間の記録は失われます

### 同期が止まったときの警告

記録が失われる前に気付けるよう、**しばらく受信が無い端末をヘッダーに表示します。**

スマホは送るものが無くても空で送信し、PCは受信時刻を記録します（`device_seen` 表）。
使用時間の有無とは別に「届いているか」だけを見るため、**スマホを使わなかった日でも
誤って警告は出ません。**

判定までの時間は `config.json` の `sync.stale_hours` で変えられます（既定24時間）。
警告にマウスを重ねると、最後の受信時刻と対処が出ます。

## データ

すべて `data/` の下に置かれ、外部へ送信されることはありません。

| ファイル | 内容 |
|---|---|
| `usage.db` | 使用時間の記録（SQLite） |
| `app_names.json` | アプリ名の対応表 |
| `sync_token.txt` | スマホとの同期に使う共有トークン |
| `window_state.json` | 小型ウィンドウの表示位置 |
| `backups/` | 自動バックアップ（下記） |
| `usage.db.bak-*` | データベース移行前の自動複製 |

**記録に保持期間の上限はありません。** 削除する処理は入っていないため、蓄積し続けます。
1年でも数MB程度に収まります。

### 自動バックアップ

**1日1回、`data/backups/` へ記録の複製を作ります。** 起動直後に一度確認し、
以後は日付が変わるたびに取得します。その日の分が既にあれば何もしません。

| 設定（`config.json` の `backup`） | 既定 | 内容 |
|---|---|---|
| `enabled` | `true` | `false` にすると取得しません |
| `keep` | `7` | 残す世代数。超えた分は古いものから削除されます |

- ファイル名は `usage-20260827-014929.db` の形式です
- SQLite のバックアップ機能を使うため、**アプリの動作中でも安全に取得できます**。
  ファイルをコピーする方式と違い、書き込み途中の状態が混ざりません
- `usage.db-wal` に留まっている記録も複製に含まれます
- 取得に失敗してもアプリは止まりません（ログに警告が残ります）

**戻したいときは**、アプリを終了してから複製を `data/usage.db` へコピーし、
`usage.db-wal` と `usage.db-shm` があれば削除してください。

複製は自分で作った名前の形式のものだけを数えます。`backups/` へ手動で置いた別名の
ファイルは、世代数の対象にならず削除もされません。

```bash
pip install -r requirements.txt      # 実行に必要なもの
pip install -r requirements-dev.txt  # テストに必要なもの
python -m pytest tests -q            # テスト
```

```bash
cd android && ./gradlew assembleDebug testDebugUnitTest lint
```

### 配色

**色は [static/style.css](static/style.css) の `:root` だけに書きます。**
JavaScript 側にも色を書くと二重管理になり、必ずずれます（実際に
グラフの6色目がCSSに無い、という状態になっていました）。

canvas や SVG のように CSS 変数を直接書けない場所へは、`common.js` の
`theme` を通して渡します。

```js
theme.color('--bar-1')      // '#8f8e8a'
theme.scale('--bar-', 6)    // 6色の配列
```

### 名前の扱い

**同一性は照合キー（`app_key`）で決め、表示名は見せる直前に決めます。**

| 種類 | 例 | どこで使うか |
|---|---|---|
| 記録名 | `chrome.exe`（PC） / `Chrome`（スマホ） | データベースに残る生の名前 |
| 照合キー | `chrome` | 束ね・制限の判定・通知の重複防止 |
| 表示名 | `Chrome` | 画面・ミニウィンドウ・通知の文面 |

**判定に表示名を使ってはいけません。** 表示名は対応表の編集で変わり、
かつ「どの行を見たか」でも変わります（PCの記録だけを見れば `chrome.exe`、
スマホも含めれば `Chrome`）。以前は制限時間を表示名で保存していたため、
画面から `Chrome` に制限を設定してもPCでは通知が出ませんでした（v2.29.0 で修正）。

対応の解決は [app/storage/display.py](app/storage/display.py) に集約しています。
`store.py` は命名の知識を持ちません。

| 用途 | メソッド |
|---|---|
| 判定に使う（キー） | `get_limits()` / `get_today_usage_by_key()` / `get_daily_seconds_by_key()` |
| 画面に出す（表示名） | `get_limits_by_name()` / `get_usage_by_range()` / `get_daily_breakdown()` |

### 画面の共通化

3画面（ダッシュボード・タイムライン・履歴）で見せ方を揃えるため、
共通の処理は `static/common.js` に集約しています。
**HTMLの骨組みは `templates/base.html` にあり、各ページは中身だけを書きます。**

| まとまり | 役割 |
|---|---|
| `format` | 時間・日付・文字の整形 |
| `devices` | 端末名の表記（`/api/status` から受け取る） |

**時間や日付の見せ方を変えるときは、このファイルだけを直します。**
以前は3画面が別々に同じ処理を持っており、片方だけ直すと表記がずれていました。

`static/style.css` の `--control-height` は、ヘッダーの高さを画面ごとに
ぶれさせないための基準です。右側にボタンが無い画面でも高さが揃います。

`html { scrollbar-gutter: stable both-edges }` で、スクロールバーの幅を
**左右へ均等に**確保しています。右だけに確保すると、中身が画面の中央から
半分ぶん左へずれます。

**アプリ名は `data/app_names.json` の `display` をそのまま表示します。**
画面側で `.exe` を落とすなどの加工はしません。表示を変えたいときは対応表を編集してください。

**ヘッダー右上は2段です。** 上段が状態表示と操作、下段が日付の切り替えです。
日付操作を持たない履歴でも段だけ確保し、3画面でヘッダーの高さを揃えています。

ヘッダーは**上端揃え**にし、左上のアプリ名と右上1段目のボタンが同じ高さに来るように
しています（`.header-left` の高さを1段ぶんに揃えている）。
ヘッダー全体の高さは、常に2段ある右側が決めます。

| 部品 | ファイル | 動作 |
|---|---|---|
| 状態・ミニウィンドウ・一時停止 | `templates/_status_controls.html` | `common.js` の `statusBar` |
| 日付の切り替え | `templates/_date_controls.html` | `common.js` の `dateBar` |

**ダッシュボードとタイムラインは日付を切り替えられます。** 日付に依存するAPIは
`?date=` を受け取り、省略すると今日になります。ダッシュボードの日／週／月は
選んだ日を含む期間を示し、**まだ来ていない日付は含めません**（今週なら月曜〜今日）。

**ヘッダー右上の状態表示と操作は3画面共通です。** 計測中かどうか、ミニウィンドウ、
一時停止は `templates/_status_controls.html` に置き、各画面から読み込んでいます。
動作は `common.js` の `statusBar` が持ち、15秒ごとに状態を確認します。

**履歴はアプリで絞り込めます。** ヘッダーの選択欄で選ぶと、そのアプリだけの
推移になります（`/api/history?app=`）。選択肢は絞り込む前の全体から作るため、
選んだあとも候補は減りません。

**ダッシュボードの統計欄は、日／週／月の切替と日付に連動します。**
実時間・アプリ数・超過はいずれも期間の解釈が要るため、`/api/usage/summary` が
まとめて求めます（画面側で足し上げると同時使用が二重に数えられ、
制限の判定も日ごとに見る必要があるため）。

**超過は「その期間に1日でも制限を超えたアプリの数」**です。制限は1日あたりの
時間なので、期間の合計ではなく日ごとに判定します。判定はこのPCの使用時間だけで
行い、通知を出すトラッカーと基準を揃えています。

**セクションの見出しには対象期間を出します。** ダッシュボードは日／週／月の切替に
連動し、タイムラインはその日付、履歴は「直近30日間」を示します。
期間の区切り方（週は月曜始まり・月は1日始まり）はサーバー側だけで決めており、
`/api/usage/<period>` が開始日と終了日を返します。画面側では計算しません。
「制限時間」は期間を持たない設定欄のため、名前のままです。

### アイコンの差し替え

アイコンの図形は `static/favicon.svg` が元になっています。差し替えるときは
このSVGを置き換えてから、以下で `.ico` と PNG を作り直します。

```bash
python tools/render_icon.py
```

`.ico` は6寸法（16〜256px）を収め、**256px 以外は DIB 形式**で書き出します。
エクスプローラーが小さい寸法の PNG を正しく扱えないことがあるためです。

**ショートカットの見た目はWindowsがキャッシュしています。** すぐに変わらない場合は
`ie4uinit.exe -show` を実行するか、サインインし直してください。

Android側は `android/app/src/main/res/drawable/ic_launcher_foreground.xml` を
手で書き換えます。SVGのパスをそのまま `android:pathData` へ移せますが、
**ランチャーが中央66%の外を切り取る**ため、`<group>` の `scaleX` / `scaleY` で
縮小して収める必要があります。
