# 仕様

このツールが何をするかを定める。どう作っているかは [architecture.md](architecture.md) を参照。

## 目的とスコープ

Windows PC とスマートフォン（Android）のアプリの使用時間を記録し、ブラウザで確認する個人用ツール。

### やること
- PC で、前面のアプリ（Chrome は登録したサイトごと）の使用時間を記録する。
- スマホの使用状況を、同じ Wi-Fi の中で PC に送って、まとめて表示する。
- 日・週・月などの期間の集計、タイムライン、制限時間の通知を表示する。
- 前日分の使用状況を、Notion のデータベースに1日1ページで登録する（任意）。

### やらないこと
- 記録の削除（保持期間の上限はない）。
- 外部への送信（Notion への日次登録を有効にした場合を除く）。
- スマホでの過去の利用状況の表示（下記「制約条件」）。

## 機能一覧

### 計測と常駐

起動すると常駐し、`http://127.0.0.1:5000` でダッシュボードを開ける。
同時に、現在使用中のアプリを示す小型ウィンドウが最前面に表示される。

アプリ名は、次の順に判定し、該当した時点で確定する（設定は [configuration.md](configuration.md#apps)）。

1. `ignore_processes` に一致 → 記録しない
2. ブラウザ（`browser_processes`）→ タイトルを `browser_site_rules` と照合
3. 実行ファイルの `FileDescription`（` - ` 以降は切り捨て）
4. 実行ファイルの `ProductName`
5. プロセス名そのまま

こうして決まった名前が、上記の**対応表で束ねられて**画面に出る。
表示を変えたいときは `data/app_names.json` の `display` を直す。

### 画面

| 画面 | 内容 |
|---|---|
| ダッシュボード | 合計と前の期間との増減、アプリ別の棒グラフ、制限時間の使用状況 |
| タイムライン | 1日を24時間の円環で表し、いつ何を使ったかを示す |
| 履歴 | 直近30日を「日 × 時間帯」の濃淡で表す。アプリを選ぶとその推移だけを見られる |

**表示はPCとスマホを合算したものである。**

**制限時間だけはこのPCの使用時間に対して働く。** 通知を出すトラッカーがPCの
使用時間で判定しているため、画面の「超過」と制限一覧の使用状況も同じ基準に揃えている。
スマホでの使用時間は含まない。

#### 前の期間との増減

合計の横に「前日比 -7時間16分」のように出る。期間の切り替え（日 / 週 / 月）に
連動し、それぞれ前日・前週・前月と比べる。

**今の期間が途中の場合、前の期間も同じ日数だけを対象にする。** 週の途中に
前の週を丸ごと比べると、日数の違いで増えて見えるためである。木曜であれば
「今週の月〜木」と「前週の月〜木」を比べる。対象の範囲は数値にマウスを乗せると
確認できる。比べる記録が無い期間では表示しない。

#### 制限時間の使用状況

設定した制限ごとに、その日の使用時間と横棒が出る。

```
X (Twitter)          17分 / 30分
████████████████░░░░░░░░░░░░░
```

- 残り5分を切ると棒が濃くなる（通知の予告と同じ基準）
- 超えると棒と数値が朱色になる
- 残り時間、または超過した時間は数値にマウスを乗せると出る

#### 時間の表記

秒数を文字列にする規則は次のとおりである。**PC本体・画面・スマホで同じ**である。

| 秒 | 表示 |
|---|---|
| 0 | `0分` |
| 1〜59 | `1分未満` |
| 60 | `1分` |
| 3600 | `1時間`（`1時間0分` とはしない） |
| 3661 | `1時間1分` |
| 3600+59分59秒 | `1時間59分`（秒は切り捨て） |
| 25時間 | `25時間`（日へは繰り上げない） |

「1分未満」を設けているのは、`0分` では使ったのかどうか分からないためである。

**この規則は3つの言語に別々に実装されている**（Python / JavaScript / Kotlin）。
コードは共有できないため、[tests/duration_cases.py](../tests/duration_cases.py) の表を
唯一の仕様とし、3つすべてを同じ内容で検証している。表記を変えるときは
この表を直せば、揃っていない実装がテストで落ちる。

#### 合計時間の数え方

**場所によって数え方が違う。** 意味が違うため、あえて揃えていない。

| 表示 | 意味 | 同時使用の重なり | 短い区間 |
|---|---|---|---|
| ダッシュボードの「合計」 | 実時間 | **除く** | 含む |
| 履歴の日付右側 | 実時間 | **除く** | 含む |
| タイムラインの円の中心 | 実時間 | **除く** | **30秒未満を除く** |
| ダッシュボードの棒グラフ | アプリごとの稼働時間 | **除かない** | 含む |

**「実時間」は、いずれかのアプリを起動していた時間である。** PCとスマホで同時に
1時間使っても、経過したのは1時間なので1時間と数える。1日の合計が24時間を
超えることはない。

**「アプリごとの稼働時間」は、そのアプリが動いていた時間である。** PCでChrome、
スマホでYouTubeを同時に1時間使った場合、どちらも実際に1時間動いているので
それぞれ1時間と数える。

```
10:00-11:00 Chrome  (PC)      ┐ 同時に使用
10:00-11:00 YouTube (スマホ)  ┘

合計（実時間）        1時間
棒グラフ              Chrome 1時間 ／ YouTube 1時間
```

##### 棒グラフを足しても「合計」と一致しない

理由は2つある。

1. **同時使用の重なりを除いていない**ため、足すと合計より大きくなる
2. **10分以上のアプリを上位10個まで**しか表示しないため、それ未満は棒に出ない

「合計」の数値にマウスを重ねると、その期間に除外した同時使用の時間が出る。

##### タイムラインだけ少し小さくなる

タイムラインは**30秒未満の区間を表示から除く**ため、その分だけ値が小さくなる。
画面に描かれている弧と数値を一致させるためで、重なりの扱いによる差ではない。

ダッシュボードと履歴は絞り込みをしないので、**この2つは常に同じ値**になる。

##### 同じアプリを2台で同時に使った場合

棒グラフだけ重なりを除けない。日ごとの集計（`usage_log`）には時刻が無く、
重なりを判断できないためである。タイムラインのアプリ別は区間から求めるため除く。

```
14:00-15:00 Notion (PC)      ┐ 30分だけ重なる
14:30-15:30 Notion (スマホ)  ┘

タイムラインのアプリ別   1時間30分
ダッシュボードの棒グラフ 2時間00分
```

### アプリ名の対応表（`data/app_names.json`）

同じアプリでも、PCとスマホでは記録される名前が違う。
そのままでは別のアプリとして数えてしまうため、**照合用のキー**で束ねている。

```
chrome.exe（PC）  ┐
                  ├→ キー "chrome" → 表示名「Chrome」
Chrome（スマホ）   ┘
```

このファイルは**アプリが自動で作成・更新する。** 中身を編集すると束ね方や
表示名を変えられる。編集後にアプリを再起動すると、**過去の記録にも遡って反映される。**

#### 中身の見かた

```json
{
  "aliases": {},
  "apps": {
    "chrome": {
      "display": "Chrome",
      "source": "auto",
      "judgement": "auto",
      "names": {
        "pc": ["chrome.exe"],
        "nothing-a069": ["Chrome"]
      }
    }
  }
}
```

| 項目 | 意味 |
|---|---|
| キー（`"chrome"`） | 照合用の値。**画面には出ない** |
| `display` | 画面に出る名前 |
| `names` | 端末ごとに、実際に記録された名前 |
| `judgement` | どう束ねたか（下記） |
| `source` | `manual` にすると `display` を自動で上書きしない |

`judgement` は3種類である。

- **`auto`** … 規則で複数の表記が一致した
- **`manual`** … あなたが指定した（`display` を変えた、または `aliases` で結んだ）
- **`single`** … 表記が1つだけで、まだ照合していない

#### 自動で束ねられる規則

1. 全角・半角を統一する
2. 末尾の `.exe` を落とす … `chrome.exe` = `Chrome`
3. 末尾の括弧書きを落とす … `X (Twitter)` = `X`
4. 大文字小文字と記号・空白を無視する … `minecraft.exe` = `Minecraft.exe`

**名前が似ていても実体が違うものは束ねない。** `YouTube Music` と `YouTube`、
`Notion Setup 7.30.0.exe` と `Notion` は別扱いのままである。

編集の手順は [usage.md](usage.md#アプリの表示名を変える統合する分ける) を参照。

### Notion への日次登録

**1日1ページ**を作り、前日分の使用状況を登録する。**既定では無効**である。

日付が変わったタイミングで自動送信し、PCが落ちていて送れなかった日は
起動時に遡って補う（既定7日まで）。同じ日を送り直すと**既存のページを更新**するため、
重複した行はできない。

#### 記録される内容

| プロパティ | 型 | 例 |
|---|---|---|
| 日付 | タイトル | `2026-08-26（水）` |
| 日 | 日付 | `2026-08-26` |
| 合計 | 数値（分） | `550` |
| 合計（表示） | テキスト | `9時間10分` |
| PC | 数値（分） | `517` |
| スマホ | 数値（分） | `121` |
| 同時使用 | 数値（分） | `88` |
| アプリ数 | 数値 | `14` |
| 最長アプリ | セレクト | `X (Twitter)` |
| 最長時間 | 数値（分） | `212` |
| 活動時間帯 | テキスト | `0〜4時、7〜10時、18〜24時` |
| 超過 | 数値 | `1` |
| 要約 | テキスト | 下記の文章 |

**「合計」を分の数値にしているのは、Notion のグラフや集計が数値型でないと使えないため**である。
読みやすさは「合計（表示）」で補う。

ページ本文には、要約の文章とアプリごとの内訳が入る。

```
8月26日（水）は9時間10分使用（PC 8時間37分・スマホ 2時間1分）。前日より2時間22分多い。
0〜4時、7〜10時、18〜24時が中心。最も長かったのはX (Twitter) 3時間32分、Claude 3時間3分、
Chrome 1時間26分。制限時間を超えたアプリが1件。

アプリごとの内訳
・X (Twitter) 3時間32分（0時 16分 / 1時 13分 / 2時 19分 / ... / 23時 38分）
・Claude 3時間3分（0時 17分 / 1時 16分 / ... / 23時 1分）
```

**要約は言語モデルを使わず、決まった形で組み立てる。** 生活の記録は数値がずれては
いけないためで、毎日同じ形になることは読み返すうえでも利点になる。

1日あたりの送信量は約2.7KB（上限500KBの0.55%）、リクエストは1〜2回である。

#### 注意

**アプリの表示名を変えると、「最長アプリ」の選択肢が二重になる。**
Notion は API から渡された名前が無ければ選択肢を自動で追加するためである
（過去の行は古い名前のまま残る）。**Notion 側で選択肢の名前を変更すれば**、
既存の行にも反映されて解消する。

**PCが止まっている間の記録は欠ける。** Notion へ送る値も同じ欠落を含む。

### スマホとの連携

同一Wi-Fi内で、スマホからPCへ使用状況を送る。**既定では無効**である。

#### 通信の範囲

有効にするとポートをLANへ開くが、**外部から使えるのは同期APIだけである。**
ダッシュボードと通常のAPIはこのPCからしか利用できず、他の端末からは拒否される。
同期APIは共有トークンで認証する。

トークンを変えたいときは `data/sync_token.txt` を削除して再起動する。

#### 同期の仕組み

- スマホは**15分ごと**に自動で送信する
- PCが起動していない間は端末に保存し、次に繋がったときにまとめて送る
- **同じ区間を何度送っても二重に記録されない。** スマホは区間ごとに
  `{パッケージ名}:{開始時刻のエポックミリ秒}` という決まった `external_id` を振り、
  PCは同じ値の区間を無視する。`usage_log` は加算せず、影響を受けた
  `(端末, 日付)` の合計を区間から計算し直して置き換える
- **OSが保持する記録は数日分である。** スマホのアプリが長期間動かないと、
  その間の記録は失われる。最低でも1日1回は送信できる状態にしておく
- 端末名 `pc` は予約語で、スマホからの取り込みには使えない
  （PC自身の記録を外部から上書きさせないため）
- スマホ側の「一時停止」は、OSの記録を止められないため**表示を隠す動作**になる

#### 同期が止まったときの警告

記録が失われる前に気付けるよう、**しばらく受信が無い端末をヘッダーに表示する。**

スマホは送るものが無くても空で送信し、PCは受信時刻を記録する（`device_seen` 表）。
使用時間の有無とは別に「届いているか」だけを見るため、**スマホを使わなかった日でも
誤って警告は出ない。**

判定までの時間は `config.json` の `sync.stale_hours` で変えられる（既定24時間）。
警告にマウスを重ねると、最後の受信時刻と対処が出る。

### 自動バックアップ

**1日1回、`data/backups/` へ記録の複製を作る。** 起動直後に一度確認し、
以後は日付が変わるたびに取得する。その日の分が既にあれば何もしない。

| 設定（`config.json` の `backup`） | 既定 | 内容 |
|---|---|---|
| `enabled` | `true` | `false` にすると取得しない |
| `keep` | `7` | 残す世代数。超えた分は古いものから削除される |

- ファイル名は `usage-20260827-014929.db` の形式である
- SQLite のバックアップ機能を使うため、**アプリの動作中でも安全に取得できる**。
  ファイルをコピーする方式と違い、書き込み途中の状態が混ざらない
- `usage.db-wal` に留まっている記録も複製に含まれる
- 取得に失敗してもアプリは止まらない（ログに警告が残る）

**戻したいときは**、アプリを終了してから複製を `data/usage.db` へコピーし、
`usage.db-wal` と `usage.db-shm` があれば削除する。

複製は自分で作った名前の形式のものだけを数える。`backups/` へ手動で置いた別名の
ファイルは、世代数の対象にならず削除もされない。

## 入出力とデータ形式

すべて `data/` の下に置かれ、外部へ送信されることはない。

| ファイル | 内容 |
|---|---|
| `usage.db` | 使用時間の記録（SQLite） |
| `app_names.json` | アプリ名の対応表 |
| `sync_token.txt` | スマホとの同期に使う共有トークン |
| `window_state.json` | 小型ウィンドウの表示位置 |
| `backups/` | 自動バックアップ（下記） |
| `usage.db.bak-*` | データベース移行前の自動複製 |

**記録に保持期間の上限はない。** 削除する処理は入っていないため、蓄積し続ける。
1年でも数MB程度に収まる。

## 制約条件

### 表示名が長いまま残るアプリがある

実行ファイルの情報から名前を取るとき、` - ` 以降の切り捨てでは短くならない例がある
（`mshta.exe` → `Microsoft (R) HTML Application host`）。また `CatchMe.exe`・
`outhold_windows.exe`・`Super Battle Golf.exe` のように名前情報を持たない実行ファイルは、
プロセス名のまま表示される。いずれも `data/app_names.json` の `display` で個別に直せる。

### ブラウザで判別できるのは登録済みのサイトだけ

Chrome のサイト判定は、`apps.browser_site_rules` のパターンとウィンドウタイトルの照合である。
登録した YouTube と X 以外のサイトは `Chrome` として記録される。

パターンはタイトルの一部との一致なので、**Chrome で開いた YouTube Music は `YouTube` として
記録される**。スマホの YouTube Music アプリは、前述の「束ねない」規則どおり別のアプリである。

URL を取得する方式（拡張機能や UI Automation）は検討したが未着手である。
ManicTime なども、URL は拡張機能から受け取る構成を採っている。
Android版では実装できない（Android版 Chrome に拡張機能が無く、タイトルに相当する
情報も取得できないため）。

### アプリ別の棒グラフは端末間の重なりを除けない

`usage_log` には時刻が無いため、同じアプリを2台で同時に使った時間を判別できない。
重なりを除いた実時間（`union_seconds`）になるのは合計だけである。別々のアプリを2台で
同時に使った時間はそれぞれ実際に使っているので、棒の合計が実時間を超えるのは正しい挙動である。

### スマホでは過去の利用状況を見られない

OSが保持する記録は数日で消えるため、スマホの利用状況画面はそれより前の日を表示できない。
遡って見るには、PC側に閲覧用のAPIを追加し、アクセス制御を見直す必要がある。

## エラー時の挙動

| 状況 | 挙動 |
|---|---|
| 設定を変更した | 起動時にしか読み込まないため、再起動するまで反映されない |
| PC が止まっていて Notion へ送れなかった日がある | 起動時に遡って補う（既定 7 日まで） |
| スマホからしばらく受信がない | ヘッダーに警告を表示する（既定 24 時間） |
| 自動バックアップに失敗した | アプリは止まらず、ログに警告を残す |
| スマホから端末名 `pc` で送られた | 取り込まない（予約語） |
